# Security Policy

## Supported Versions

This repository currently follows a branch-based support model.

- Security fixes are applied to `main`.
- We do not currently maintain long-lived release branches.
- If release branches are introduced later, this policy will be updated.

| Version                | Supported          |
| ---------------------- | ------------------ |
| `main`                 | :white_check_mark: |
| older commits/branches | :x:                |

## Reporting a Vulnerability

Please report security vulnerabilities privately using GitHub Security Advisories:

1. Go to the repository Security tab.
2. Select "Report a vulnerability".
3. Include reproduction details, impact, and affected files/paths.

Do not open public issues for suspected vulnerabilities.

### What to include

- A clear description of the issue and impact.
- Steps to reproduce or a minimal proof of concept.
- Any known mitigations or fix suggestions.
- Your contact details for follow-up.

### Response expectations

- Initial triage acknowledgment target: within 3 business days.
- Severity assessment and next-step update target: within 7 business days.
- If accepted, we will coordinate remediation and disclosure timing with you.

### Disclosure policy

- We follow coordinated disclosure.
- After a fix is available (or mitigation is in place), we will publish a security advisory with affected scope and remediation guidance.
